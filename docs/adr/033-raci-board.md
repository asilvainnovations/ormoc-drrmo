# ADR-033: Interactive RACI board — Annex 1-F matrices searchable, color-coded and linked to protocols; CDRRMO Head maintains assignments (v1.19.0)

Status: Proposed, 13 Nov 2026, by the lead assessor (Alvin M. Silva). For the CDRRMO Head.

## Context

MOO Annex 1-F (Integrated RACI Accountability Framework) assigns Responsible / Accountable / Consulted / Informed for every governance and operational activity, and Chapters 1–10 carry the same mapping wherever a workflow, process flow or SOP appears. On the platform that mapping existed only as text: nothing linked the Library, the DRRM protocols and the EOC screens to who does what, and a duty officer could not answer "who is Accountable for convening the PDRA?" without reading the annex. The City also wants the same RACI lens on the manual documents themselves — who reviews, edits, validates and approves them — and wants the CDRRMO Head to keep the assignments current as the organization changes (Annex 1-F directs exactly that review).

## Decision

1. **Three reference tables** (migration `20261113002900_raci_board.sql`): `raci_matrices` (the five Annex 1-F matrices 6.1–6.5 plus `DOC`, the manual document-governance matrix), `raci_activities` (one row per activity, optional `template_id` linking to the protocol or workflow that carries it out, optional `note` for the Manual's legal caveats), and `raci_assignments` (one row per activity–actor–duty, with an optional `qualifier` for cells like "R (documentation)" or "A/R within mandate"). Actors are positions, offices or bodies — never personal names (RA 10173), matching the Manual. `v_raci_board` denormalizes the three for the UI.
2. **One-A is a warning, not a constraint.** Annex 1-F says there should *normally* be one Accountable per activity, and its own cells share accountability ("A/R within mandate" across technical offices). The board therefore flags activities with zero or several A's instead of blocking them; a hard unique constraint would contradict the approved Manual text.
3. **Reads offline, writes online.** Matrices are reference data: any active user reads them from the local store (ADR-003). Changing an assignment is an authority action (ADR-006): RLS grants insert/update/delete only to `cdrrmo_head` and `admin`, and the client sends those edits with `updateOnline`/direct online writes — never queued. This mirrors the existing rule that only the CDRRMO Head approves manual content.
4. **RACI board screen** (`src/features/raci/`, route `/raci`). Search by activity, actor, protocol code or SOP reference against Dexie; results render as a color-coded board grouped by matrix: R navy, A dark green, C gold, I white (tokens `raci-r`/`raci-a`/`raci-c`/`raci-i` in `tokens.css`; the white chip keeps a visible border and dark text in both color schemes for WCAG 2.1 AA). Each chip's tooltip gives the duty definition; activity notes show the Manual's caveat verbatim with "The official text governs." Activities with ≠1 Accountable carry a warning badge. A dashboard card on Today links in, and the board is linked back from the protocol detail and the Library document page, closing the loop the City flagged (features did not refer to each other's tools).
5. **Document-governance matrix (`DOC`).** Draft/edit, technical review, validation, approval and publication of manual documents are seeded as RACI activities whose actors are the platform roles that already enforce those transitions (`author`, `validator`, `lead_office_focal`, `cdrrmo_head`), so the board explains the rules the guards enforce rather than creating a parallel permission system.
6. **Seeded from the Manual, not invented.** `scripts/raci_seed.py` emits `supabase/seed/parts/37_raci.sql` transcribing Annex 1-F matrices 6.1–6.5 verbatim (including qualifiers and footnote caveats), plus the DOC matrix, with deterministic uuid5 ids; template links are made only where the activity plainly matches an existing protocol or workflow code. Seeds never mark anything approved; the CDRRMO validates the board at the workshop like any manual content.

## Consequences

- The RACI board is an explanation layer: it never grants authority. Annex 1-F's own caveat ("the RACI matrix does not create legal authority") is shown on the screen, and statutory assignments in the Manual prevail over any edit.
- A Head edit is audited like any other change (`app.audit` via `app.track`) and optimistic-concurrency protected (`version` + PT409).
- New chapters or protocols extend the board by adding seed rows and, where relevant, a `template_id` link; no schema change is needed.
- The color tokens are reserved for RACI (like the EOC alert colors are reserved for the alert band): other screens do not reuse the navy/green/gold/white duty combination.
